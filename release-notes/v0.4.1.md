## Breaking: `onenote serve` is locked down

- A loopback server with no key now generates a random 32-byte API key for the run and prints it once on stderr, with a ready-to-copy `Authorization: Bearer …` line. Scripts and agent configs that called a keyless server must send that key, set their own with `--api-key` / `ONENOTE_API_KEY`, or start the server with `--allow-keyless` (loopback only; any local process can then read and edit notebooks).
- Binding a non-loopback address always requires a key. `ONENOTE_ALLOW_INSECURE_SERVE` is no longer honoured.
- The wildcard CORS policy is gone. Allow a browser origin explicitly with `--cors-origin <ORIGIN>` (exact match).
- Requests whose `Host` header is not `127.0.0.1`, `localhost`, `[::1]`, the `--bind` value or an `--allowed-host` entry get `421 Misdirected Request`.
- API keys are compared in constant time. (NEW-01)

## Fixes

- The browser login success page says OneNote instead of Outlook. (ON-29)
- Markdown links whose URL contains balanced parentheses, such as Wikipedia disambiguation links, are no longer cut at the first `)`. (ON-32)
- README no longer claims SharePoint site notebooks are discovered automatically. (ON-04 wording)
- A section listing in which some section-group requests failed keeps the previously cached sections and pages and reports a warning, instead of pruning them. (ON-01)
- `--include-teams` queries up to 100 joined Teams (`ONENOTE_MAX_TEAMS`, `1`–`500`; background sync keeps 25) and warns when the list was truncated. (ON-02)
- A sign-in without `Team.ReadBasic.All` / `Notes.Read.All` now warns that Teams notebooks were skipped and how to sign in with your tenant. (ON-05)
- Title lookup with `--section` reads up to 5,000 pages instead of 100, and duplicate titles past row 500 of the cache are reported as ambiguous. (ON-03)
- Sections with more than 500 pages no longer lose cached pages: pruning follows Graph's "more pages" signal, and explicit refreshes read up to 2,000 pages. (ON-08)
- `search --section <name>` resolves the section first and filters in SQL, so plain section names work and `has_more` is exact. (ON-10)
- `delete` resolves the page before asking and shows its title, location and key in the prompt; non-interactive use still refuses before any network call. (ON-22)
- Saving settings no longer writes values that come from environment variables into `config.toml`. (ON-12)
- The background daemon opens the same per-account cache as the CLI and TUI, and a CLI that knows its account no longer attaches to an anonymous daemon. (ON-07)
- `POST` and `PATCH` requests (page creation, append) are no longer replayed after a `502`/`504`, which could duplicate content; the error says the request may have been applied. `DELETE` replays treat a following `404` as deleted. (ON-20)

## Enterprise networks

- HTTPS now trusts the operating system's certificate store in addition to the bundled Mozilla roots.
- `ONENOTE_EXTRA_CA_PEM` adds a PEM root certificate or bundle (an unusable file is an error naming it). `SSL_CERT_FILE` and `NODE_EXTRA_CA_CERTS` are also loaded; an unusable file there is a stderr warning.
- A TLS failure caused by an unknown issuer now includes a hint naming these variables, and `onenote doctor --online` prints it (`online_probe_hint` in `--json`). Certificate verification cannot be disabled.

## MCP

- Tool descriptions in `tools/list` state which calls reach Microsoft Graph and which options are expensive (for example `search_pages` with `refresh: true` runs a full account sync). Tool names and arguments are unchanged.

## Compatibility

- `has_more` in section page lists and section-filtered search is now always a boolean where it could previously be `null`.
- `onenote doctor --json` adds `online_probe_hint`.
